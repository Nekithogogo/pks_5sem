# КР №3 — Автосалон: заявки на тест-драйв

Отдельное серверное приложение на Spring Boot 3.5 и веб-клиент для системы автосалона из КР №1–2. Основная сущность — заявка на тест-драйв; справочник — автомобили. Клиенты и автомобили связаны с заявками внешними ключами. Настольное JavaFX-приложение остаётся отдельным клиентом.

## Запуск в Windows

1. Запустите Docker Desktop.
2. Откройте эту папку и запустите `start.bat`. При первом запуске скачиваются образы и Maven-зависимости. Это может занять несколько минут.
3. Откройте <http://localhost:8080/>. Адрес проверки сервера: <http://localhost:8080/actuator/health>.
4. Логин и первоначальный пароль находятся в созданном файле `.env`: `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`. При первом входе система попросит установить новый пароль; временный пароль после этого больше не действует.
5. Для остановки без удаления данных запустите `stop.bat`. Повторный `start.bat` сохраняет пользователей и заявки.

Swagger доступен администратору после входа и смены временного пароля: <http://localhost:8080/swagger-ui.html>. Данные PostgreSQL размещены в отдельном Docker volume; порт БД по умолчанию `55434`. При первоначальном создании серверной базы Docker загружает сохранённый снимок данных КР №1; последующие запуски не перезаписывают данные.

Файл `.env` генерируется автоматически и содержит секреты. В `.env.example` приведены только примеры параметров. Если меняется порт приложения, обновите `CORS_ALLOWED_ORIGINS` в `docker-compose.yml`, если доступ к API нужен с другого origin.

## Что реализовано

- Роли `VIEWER`, `MANAGER`, `ADMIN`; BCrypt, access JWT, refresh-сессии с ротацией и отзывом, блокировка после неудачных входов, обязательная смена временного пароля.
- Заявки: UUID и номер, клиент, автомобиль, дата и длительность, статусы `NEW`, `CONFIRMED`, `COMPLETED`, `CANCELLED`, `NO_SHOW`, обратный звонок, теги, расчётный приоритет, версия, архив и восстановление. Физическое удаление — администратору.
- Поиск и фильтры по автомобилю, статусу, обратному звонку, приоритету, тегу, архиву и длительности; ограниченная серверная пагинация и сортировка. Фильтры строятся через JPA Criteria, без конкатенации пользовательского SQL.
- Администрируемый справочник автомобилей, создание клиентов, заметки, массовые операции с результатом по каждой записи, предварительная проверка и импорт CSV, экспорт текущего фильтра.
- Аналитика, управление пользователями, журнал аудита с correlation ID, OpenAPI и единые JSON-ошибки.

## API

Все прикладные запросы, кроме входа, refresh и health, требуют `Authorization: Bearer <accessToken>`. Для браузера refresh-токен хранится в HttpOnly cookie; для Android можно передать `clientType: NATIVE` и использовать возвращённый refresh-токен.

Основные адреса: `/api/auth/login`, `/api/auth/refresh`, `/api/auth/logout`, `/api/auth/me`, `/api/auth/change-password`, `/api/requests`, `/api/requests/{id}`, `/api/requests/{id}/restore`, `/api/requests/{id}/permanent`, `/api/requests/bulk`, `/api/requests/{id}/notes`, `/api/requests/import/preview`, `/api/requests/import/apply`, `/api/requests/export`, `/api/cars`, `/api/clients`, `/api/analytics/summary`, `/api/admin/users`, `/api/admin/audit`. Методы и модели можно посмотреть в Swagger.

Для GET `/api/requests` поддерживаются параметры `q`, `carId`, `status`, `callback`, `priority`, `tag`, `archived` (`false`, `true`, `all`), `durationMin`, `durationMax`, `page`, `size` (1–100) и `sort`. Поля сортировки: `scheduledAt`, `duration`, `status`, `client`, `car`, `createdAt`, `externalId`; например `sort=scheduledAt,desc`.

CSV — UTF-8, запятая как разделитель, первая строка:

```csv
externalId,clientPhone,carVin,scheduledAt,durationMinutes,status,comment,callbackRequested,tags
TD-100,+79161234501,XW7BF4FK10S123451,YYYY-MM-DDT12:00:00,30,NEW,Нужна консультация,true,повторный|срочный
```

В примере замените YYYY-MM-DD на дату в будущем в пределах 60 дней. Укажите телефон существующего клиента и VIN существующего автомобиля. Режимы импорта: `CREATE_ONLY` и `UPSERT`. Предпросмотр проверяет правила заявки и пересечения строк файла, а импорт повторно проверяет данные при применении: между этими действиями данные могли измениться. Для защиты от формул Excel значения, начинающиеся с `=`, `+`, `-`, `@` или апострофа, экранируются апострофом; экспортированные значения корректно восстанавливаются при повторном импорте. Теги разделяются `|`; для символа `|` внутри тега используйте `\|`, для обратной косой черты — `\\`.

## Связь с КР №1

`V1__base.sql` воспроизводит исходную структуру `clients`, `cars`, `test_drive_requests`, а следующие миграции добавляют UUID и необходимые для API поля и таблицы. Старые числовые ключи и связи сохраняются. Изменения автомобиля или заявки из прежнего JDBC-клиента увеличивают `version` через триггеры.

КР №3 сейчас подключена к отдельной серверной базе `autosalon_kr1`, в которую перенесены фактические таблицы и данные существовавшей КР №1. После переноса содержимое всех трёх исходных таблиц сверено с оригиналом. Flyway пометил исходную схему как версию 1 и применяет последующие миграции. V5 добавляет ограничения PostgreSQL от пересечений расписания и индексы поиска. Исходная база КР №1 и прежняя демонстрационная база КР №3 сохранены.

Это снимок на момент переноса: изменения в старом консольном приложении и серверной базе КР №3 автоматически не синхронизируются. JavaFX также остаётся отдельным настольным клиентом со своей прежней базой. Такая схема позволяет запускать все три работы независимо.

Снимок для первоначального создания контейнерной базы находится в `local-data/kr1-data.sql`, а полная резервная копия исходной КР №1 — в `local-data/kr1-backup.dump`. Эти локальные файлы могут содержать персональные данные и исключены из Git. При обычных повторных запусках импорт не выполняется, и изменения в серверной базе сохраняются.

## Проверки

В папке backend: `mvn test`. Проверяются загрузка Spring Context, разграничение прав, фильтр заявок, расчёт приоритета, сохранение местного времени, CSV и безопасность refresh-сессий. Для проверки в реальной PostgreSQL отдельно выполнялись вход, операции с заявкой, заметками, CSV, аналитикой и архивом. Приложение собирается на Java 21 или более новой версии; Docker использует Java 21.

## Публикация на GitHub

В репозитории исходные персональные данные и снимки базы не публикуются. При первом запуске серверная база создаётся без пользовательского снимка; миграция добавляет демонстрационные данные, также клиентов и автомобили можно добавить в интерфейсе. Описанные выше локальные снимки относятся к исходному компьютеру и не включены в репозиторий.
